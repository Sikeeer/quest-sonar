# Quest 3: карта препятствий, облако точек и звуковой сонар

Версия: **v1-audio-sonar** (дата среза 2026-10-23)
Статус: **код не компилировался и не проверялся на шлеме.** Всё написано «вслепую», первая сборка может потребовать мелких правок.

## Цель
Помощь слепым и слабовидящим при ходьбе: Quest 3 измеряет расстояния датчиком глубины (Depth API), а приложение превращает их в пространственные звуки. Это дополнение к трости или собаке-проводнику, а не замена.

## Из чего состоит проект

| Файл (`Assets/`) | Роль |
|---|---|
| `ObstacleMap.cs` | Ядро. Пускает лучи по глубине, строит карту препятствий (2D-сетка, вид сверху), даёт события и API |
| `DepthPointCloud.cs` | Отладочная визуализация: выключает passthrough, рисует облако точек глубины |
| `AudioSonar.cs` | Превращает точки глубины в пространственные звуки + вибрацию |
| `QuestRoomScanner.cs` | Только HUD со статусом (раньше рисовал рамки комнаты из MRUK, теперь MRUK не используется) |

Все четыре скрипта создаются сами при старте сцены (`RuntimeInitializeOnLoadMethod`). Вешать на объекты ничего не нужно. Параметры видны в Inspector у созданных объектов во время игры.

## Что нужно в сцене
- `OVRCameraRig` (голова = `centerEyeAnchor`; `Camera.main` не используется, в сцене два объекта с тегом MainCamera).
- `EnvironmentRaycastManager` (Meta XR Core SDK, Depth API) и разрешение на сцену на шлеме.
- Для облака точек: `OVRPassthroughLayer` (если его нет, будет только чёрный фон).
- Для лучшего звука: **Meta XR Audio SDK** и `Project Settings → Audio → Spatializer Plugin = Meta XR Audio`. Без него звук работает на обычной стереопанораме Unity.
- Манифест: PASSTHROUGH, USE_SCENE, USE_ANCHOR_API, HAND_TRACKING, supportedDevices `quest|quest3|quest3s`. Строки `BOUNDARYLESS_APP` в манифесте **нет** (она убирает системную границу Guardian; Project Setup Tool при Overwrite её удаляет).
- MRUK больше не нужен этим скриптам. В сцене его можно оставить или убрать.

## Как это работает

```
Quest 3 depth sensor
        │  EnvironmentRaycastManager.Raycast (синхронный луч)
        ▼
 ObstacleMap.Scan()  ── каждый кадр, N лучей (по бюджету времени)
        │   ├─ OnDepthHit(Vector3)  ──► DepthPointCloud (частицы)
        │   │                       └─► AudioSonar (сектора → звук)
        │   └─ карта: log-odds в клетках 0.1 м, 3 высотных слоя
        ▼
  минимап, плитки на полу, API (IsOccupied, DistanceAlong, ...)
```

### 1. ObstacleMap (ядро)
1. **Лучи.** Каждый кадр пускается столько лучей, сколько влезает в `scanBudgetMs` (5 мс), от `minRaysPerFrame` (32) до `maxRaysPerFrame` (512). Направления берутся по последовательности Хэлтона (равномерное покрытие, а не один и тот же набор). Веер привязан к взгляду: по горизонтали ±55° (`yawRange` 110°), по вертикали от −25° (вверх) до +45° (вниз).
2. **Зона под ноги.** 35% лучей (`footShare`) идут в узкий сектор впереди-внизу: ±35° по горизонтали, 10–50° вниз. Нужна для ступенек и порогов.
3. **Классификация попадания** по высоте над полом:
   - ниже `stepHeight` (0.15 м): пол, проходимо;
   - выше `headClearance` (1.9 м): потолок, препятствием не считается;
   - между: препятствие, +`hitAdd` в клетку.
4. **Очистка.** Вдоль луча до точки попадания клетки получают `missAdd`: исчезнувшие предметы стираются.
5. **Три высотных слоя** (до 0.6 м, до 1.2 м, выше), чтобы луч над низким предметом не стирал его.
6. **Пол** определяется по лучам вниз (`floorY`, учится сам; до первого определения: высота головы − `fallbackEyeHeight` 1.6 м).
7. **Забывание.** Все значения клеток плавно уходят к нулю с постоянной времени `memorySeconds` (4 с). Пустые клетки удаляются раз в 2 с.
8. **Визуализация.** Миникарта 10×10 м перед глазами (вверх = направление взгляда), плитки препятствий на полу (до 250 шт., радиус 3 м): зелёные, жёлтые (< 1.2 м), красные (< 0.6 м).
9. **API:** `Instance`, `IsOccupied(Vector3)`, `IsOccupiedCell`, `DistanceAlong(dir, max)`, `ToCell`, `CellCenter`, `ClearMap()`, события `OnDepthHit`, поля `floorY`, `nearestDistance`, `nearestPoint`, `occupiedCount`, `lastRays`, `lastHits`, `raysPerSecond`, `scanMs`, `statusCounts`.

### 2. DepthPointCloud (облако точек)
- Подписывается на `OnDepthHit`, рисует точки частицами (`ParticleSystem`). Цвет = высота над полом (синий внизу, красный вверху).
- Точки живут `pointLifetime` = 2.5 с, до `maxEmitPerFrame` = 120 в кадр, максимум 30 000.
- Выключает passthrough (чёрный фон). Кнопка **B или Y** переключает камеры.
- **Автовключение камер сейчас отключено** (`autoPassthroughBelow = 0`). Если поставить 0.5, камеры включатся при препятствии ближе 0.5 м или при 3+ лучах за кадр ближе 0.4 м.

### 3. AudioSonar (звук)
1. Поле зрения делится на 5 секторов по горизонтали. По `OnDepthHit` в каждом сектора берётся **ближайшая** точка за окно 0.12 с (пол и потолок отбрасываются).
2. Звучат только 3 ближайших сектора (`activeSectors`), между началами звуков минимум 0.06 с.
3. **Расстояние:**
   - частота писков от 0.8 с (далеко, 3 м) до 0.09 с (близко);
   - громкость от 0.25 до 0.9;
   - нота пентатонической гаммы: ближе = выше (6 ступеней).
4. **Высота:** точка ниже 0.9 м над полом = тёплый «щипок», выше = «колокольчик».
5. **Направление:** источник звука стоит в сторону точки, не дальше 1.5 м от головы (громкость задаётся программой). Нужен `AudioSource.spatialize` и Meta XR Audio.
6. **Опасность:** ближе 0.6 м почти сплошной тон + вибрация обоих контроллеров.
7. **Обрыв/ступеньки вниз:** если за окно 3+ луча попали ниже пола на 0.3 м и больше, звучит нисходящий сигнал, повтор каждые 0.7 с.
8. **Кнопка A или X** включает и выключает звук (короткий подтверждающий сигнал).
9. Звуки генерируются программой (без файлов): мягкая атака, экспоненциальное затухание, ~5% шума для лучшей локализации.

Основания выбора (исследования по сонификации для слепых): [обзор](https://www.journals.pan.pl//Content/102689/PDF/aoa-2016-0040.pdf), [IJHCS](https://opinvisindi.is/bitstream/handle/20.500.11815/702/paper_IJHCS_pre-print.pdf?sequence=3). Главное: приятные тембры вместо резких писков, ограничение числа одновременных звуков, окружающие звуки не блокировать, подбирать параметры вместе со слепыми.

### 4. QuestRoomScanner (HUD)
Текст перед глазами: ближайшее препятствие, высота пола, число занятых клеток, «Скан: FPS/с, лучи попадания/всего, лучей/с, мс на лучи», статусы лучей (почему нет попаданий). Цвет: белый, жёлтый (< 1.2 м), красный (< 0.6 м).

## Управление

| Кнопка | Действие |
|---|---|
| B / Y | Включить или выключить passthrough (облако точек) |
| A / X | Включить или выключить звук сонара |

| Параметр | Значение | Где |
|---|---|---|
| `scanBudgetMs` / `minRaysPerFrame` / `maxRaysPerFrame` | 5 / 32 / 512 | ObstacleMap |
| `useTimeBudget` (выкл. = фиксированные `raysPerFrame` = 64) | true | ObstacleMap |
| `maxDistance` | 4 м | ObstacleMap |
| `cellSize` | 0.1 м | ObstacleMap |
| `memorySeconds` | 4 с | ObstacleMap |
| `hitAdd` / `missAdd` / `occThreshold` | 0.9 / −0.35 / 1.0 | ObstacleMap |
| `warnDistance` / `dangerDistance` | 1.2 / 0.6 м | ObstacleMap |
| `pointLifetime` / `maxEmitPerFrame` / `maxPoints` | 2.5 с / 120 / 30000 | DepthPointCloud |
| `sectors` / `maxRange` / `windowSec` / `activeSectors` | 5 / 3 м / 0.12 с / 3 | AudioSonar |
| `minInterval` / `maxInterval` | 0.09 / 0.8 с | AudioSonar |
| `dropDepth` / `dropMinVotes` | 0.3 м / 3 | AudioSonar |

## Известные ограничения и риски
- **Не проверено на шлеме и не компилировалось.**
- Датчик не видит стекло, зеркала, тонкие предметы (ножки стула), плохо работает на ярком солнце. Быстро движущихся людей видит с задержкой.
- Без passthrough реальный мир не виден. Автовключение камер отключено по просьбе пользователя.
- Определение обрыва зависит от `floorY`, которая учится по лучам и может «уплывать». Возможны ложные срабатывания.
- Тип точки (низкий/высокий тон) определяется по высоте самой ближайшей точки сектора: стена тоже считается «низкой», если ближайшая её точка низко.
- Стоимость `Raycast` у Meta неизвестна заранее, смотри «мс» в HUD. Если лучей мало, следующий шаг: читать текстуру глубины шейдером (тысячи точек за кадр).
- Идентификатор пакета Meta XR Audio SDK (`com.meta.xr.sdk.audio`) назван по памяти. Если «Add package by name» не находит его, ищи в Package Manager.
- Руки в поле зрения тоже дают близкие точки.

## Что исправлено по сравнению с прошлой версией
- Веер лучей раньше был от −50° до +25° и смотрел больше вверх, чем вниз (в Unity плюс = вниз). Теперь −25° … +45°.
- Убран MRUK из `ObstacleMap` и `QuestRoomScanner`.
- Добавлены события `OnDepthHit`, бюджет лучей по времени, забывание, зона под ноги.

## Идеи на потом
1. Распознавание ступенек (подъём): повторяющиеся уступы 15–20 см перед пользователем.
2. Режим «пинг» по кнопке: проход слева направо за 1–2 с.
3. Кластеризация точек в объекты с рамками.
4. Голосовые подсказки для редких событий («дверь справа, 2 м»).

6. Чтение текстуры глубины шейдером вместо лучей.

## Как вернуться к этой версии
Репозиторий git содержит:
- тег `v1-audio-sonar`;
- ветку `stable/v1-audio-sonar` (только эта версия, не менять);
- ветку `dev` (для дальнейшей работы).

```bash
git checkout stable/v1-audio-sonar        # посмотреть эту версию целиком
git checkout dev                          # вернуться к работе
git checkout v1-audio-sonar -- Assets/    # откатить файлы в текущей ветке к этой версии
```
Без git: папка `snapshots/v1-audio-sonar/` содержит копию всех четырёх файлов.
